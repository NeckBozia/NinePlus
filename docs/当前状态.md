## 给新会话的坑（这些都真踩过）

### 1. `swift test` 不编译任何界面代码

它只编译 `mini-ninebot/Shared/`（NineBotCore）。视图、ViewModel、Widget 只有 `Xcode build` 那个 job 编译。

**已经出过事**：改了 `RideDisplayMetric` 的构造函数签名，漏掉视图里 7 个调用点，383 个测试全绿，Xcode 构建挂掉。

**做法**：改签名用全局替换，改完再用正则核验所有调用点，不要只替换第一处。

### 2. 中文不能当值用

详见 `CLAUDE.md`。这个项目踩过至少 4 次。

### 3. 不要替用户做产品决策

有分歧就写进 `pending-decisions.md`，格式是「现状 / iOS 怎么做的 / 分歧点 / 建议决定时机」。这条被反复强调过。

### 4. 查 CI 状态只能用 MCP 的 GitHub 工具

`curl` 打 GitHub API 会拿 403（这个环境只放行 MCP 通道），而且失败是静默的 —— 轮询脚本会一直转到超时却什么都没查到。用 `mcp__github__actions_list` + `mcp__github__get_job_logs`（带 `failed_only`）。**也不要用 WebFetch 查 CI**，它给过错的结论。

### 5. agent 的产出要核对

派出去的 agent 写的规格质量不错，但引用的行号和数值一律要抽查。已经抓到过若干处需要修正的引用。
